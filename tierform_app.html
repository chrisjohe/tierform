Where your data lives

Everything stays on your machine. Names, groups and photos are read, resized and drawn entirely inside your browser. While you edit and while you export, this app makes no network requests at all — nothing is uploaded, and there is no analytics, no telemetry and no error reporting. The links on this page are ordinary links: they reach the network only if you click one.

Nothing is stored in the app between visits — not even a draft. The roster file is your saved work, so save before you close the tab.

Handle roster files with care

A roster file holds names, groups and the photos themselves, embedded in full. In most places that makes it personal data, with the obligations that follow. The same is true of every export: the PNG, the PDF and the SVG all carry the faces and the names.

So share a roster, a chart or an export only with people entitled to see who is in the team — and remember that emailing a chart to a wide list is a disclosure like any other.

Opening a roster from someone else is the one risky action here. The whole file is checked before anything is adopted, and a file whose structure cannot be trusted is refused without touching the roster you have open. Each photo is read as bytes first — its format has to match the type the file claims, and the size it declares has to be within the limits — before the browser is asked to decode it. A photo that fails costs only that photo: the person keeps their name and grade, and you are told what was wrong.

That is a size and format check, not a guarantee about hostile images, so the safe habit is still the ordinary one: open files from people you actually know.

Shortcuts & tips

  • Ctrl/⌘+Z undo · ⇧+Ctrl/⌘+Z redo
  • Esc closes a menu or dialog
  • Behind Add people's arrow: Add list… takes a pasted list and Import CSV… reads the same columns from a file — both land in one preview
  • Paste a list: Name, Grade, Group, Role — tab, comma or semicolon
  • Starting from nothing? With no grades yet the Add dialog asks for your first grade, and a pasted list builds the grades from its own Grade column
  • Drop JPEG or PNG photos on the chart or on the sidebar — one that matches a photo-less person by name attaches to them
  • File names become names — First_Last.jpg, and Last, First is turned around
  • Click a photo to reframe it: drag to pan, slider to zoom
  • Type a group wherever one is asked for: matching text joins that group, new text starts one. Reorder, rename or merge them under Structure ▸ Group; groups show in each person's subline and are the rows of the Matrix layout
  • On a grade: Attach removes the gap to the previous grade · Share combines the two grades on one surface — band, lane, cell or column, whichever the layout draws
  • A grade too crowded for one row: split its people across two grades with the same fill and Attach the second — the pair reads as one deep band
  • Switching layouts loses nothing: the triangle angle, a grade's alignment, every setting is kept and found again when you switch back
  • Structure ▸ Templates replaces the whole grade structure and sets the layout, accent and text colour to match; Clear grades empties it instead. Both are unavailable while anyone is on the roster — there is nowhere to put a person whose grade has gone. Remove the people first, or move them to a grade you are keeping.
  • Nothing saves itself: the roster lives in the file you save, and the icon beside the file name shows when changes are unsaved
  • PNG and PDF are rasterised here and keep their look; SVG uses the fonts of whoever opens it

Where this works

TIERFORM is optimised for desktop. Other form factors are only partly supported: on a phone or a small tablet the roster and the chart take turns instead of sharing the screen.

Browsers

Copy PNG needs the browser's clipboard API, which Safari and Chrome do not grant to a page opened from a file. Where it is unavailable the button is switched off and says so — use Export ▸ Export PNG, which writes the file to disk instead, or serve the file over http and Copy PNG comes back.

If you find a problem

Report it privately: open a security advisory on the project's GitHub page, under Security ▸ Report a vulnerability, or here.

Report a vulnerability

The report stays between you and the maintainer until a fix is published. Please do not open a public issue for a vulnerability.

Include what you did, what happened, and which browser and version you used. A roster file that reproduces the problem is the most useful thing you can attach, but strip any real names and photos first, since a roster file is personal data.

Do not expect an acknowledgement immediately. This is a small project maintained by one person, so please allow a reasonable time to fix before disclosing publicly. Reports are welcome even if you are not sure the behaviour is a bug.

What counts

The app runs on your machine with no server and no network access, which rules out most of the usual categories and concentrates the risk in one place: the files it opens. A roster file that runs script, that gets the app to reach the network, or that quietly corrupts or drops part of the roster you already have open. An image that escapes the size and shape limits. An export that carries more than the chart shows.

Outside that: the app modified, minified or served in pieces; anything that needs someone to already be running code on your machine; and an absurdly large file, where the worst case is a tab you have to close.

What happens to a roster file when you open one is described under Privacy.

The full account — how untrusted input is handled at each step, and a content security policy if you host a copy — is in SECURITY.md in the repository.
