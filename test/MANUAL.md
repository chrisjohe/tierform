# Manual test plan and baseline

Five automated suites cover geometry, DOM wiring, the document model, the
roster fixtures and import validation. Three things they cannot cover, because
there is no real browser in the loop: **whether the chart actually renders**, **whether PNG and PDF export**,
and **whether the app is usable by keyboard and screenreader**. Those are the
checklists below.

Run the suites first — a manual pass over a build that fails them wastes an hour:

```sh
node test/harness.js     # geometry
node test/dom.js         # DOM wiring, ids, house rules
node test/document.js    # document model, undo, defaults()
node test/fixtures.js    # roster files, and the roster panel it builds
node test/import.js      # what the validator refuses and repairs
```

No Node on the machine? On macOS every suite also runs under JavaScriptCore
with no install at all — `osascript -l JavaScript test/<suite>.js` — the same
assertions, only slower.

## Baseline

The table below records the current build's size, its history-memory cost and
its suite counts, so a regression shows up as a number that moved. The last
three rows are the ones to update.

| | Value |
|---|---|
| History memory, 30 people / 25 photos / 10 steps | 1.05 MB |
| **Current build** — `tierform_app.html`, recorded 2026-08-13 | 956 719 bytes, 10 308 lines |
| Suites | harness 15 389 · dom 3 076 · document 1 298 · fixtures 801 · import 777 = **21 341** |
| App version | `const VERSION` and the About release label, both `2026.8` |

`tierform_app.html` is the deliverable. Timestamped working copies are banned
from the project — version control is the checkpoint — and `test/dom.js` fails
the build if README, NOTICE or the app itself names a `.backup-*.html` file.

### What each fixture is for

Measured, not assumed — these verdicts are what `test/fixtures.js` and
`test/import.js` pin, and what a manual Open of each file must show:

| Fixture | Verdict |
|---|---|
| `current.json` | accepted, 0 repairs |
| `legacy.json` | accepted, 0 repairs — the validator fills in everything it omits; absent is not a repair |
| `pyramid-zero.json` | accepted, **angle stays 0** — `0`, `false` and `""` are real choices, never "empty" |
| `malformed.json` | refused: "the file is not valid JSON" |
| `bad-refs.json` | **refused**: two grades share the id "dup" |
| `bad-values.json` | accepted, **10 values repaired** and counted in the toast |
| `injection.json` | accepted, **5 repairs, SVG clean** |
| `unicode.json` | accepted, 0 repairs |
| `photos.json` | accepted; 3 photos dropped as undecodable, 1 resized to its real dimensions |

Every fixture that still reaches the renderer produces finite geometry and an
SVG containing no `<script>`, no `on*=` attribute, no `javascript:` URL and no
`href` that is not an embedded image.

Fixtures are generated by `test/fixtures/generate.py` — regenerate rather than
hand-edit, so a change is one reviewable diff. They contain **no real roster
data**; every name is invented, and photos are a 1×1 JPEG rather than a real
face. Oversized inputs (a 10 000-character name, thousands of people, a photo
over the size limit) are built in-memory by `test/import.js` instead of being
committed, because an 8 MB fixture is not worth version-controlling.

## Core flows

Run after every phase. Ten minutes when nothing is broken.

### Document
- [ ] Every modal action row is centred: New/Open confirmations, Save As and
      Add grade prompts, both Paste-list states, and the Info dialog.
- [ ] **New** — Start ▸ New on a dirty document opens the in-app dialog, whose
      button reads "Discard and start new"; accepting empties the canvas — no
      grades and no people, Templates under Structure being the route to a
      starting structure; the title bar reads "Untitled roster".
- [ ] Cancelling that dialog really cancels — the roster is untouched.
- [ ] **Save** — writes `<stem>.json`; the status goes back to the saved icon;
      the title bar shows the stem.
- [ ] **Saved / not-saved-yet / unsaved status** — three states, visible as text
      beside the icon (hovering the strip shows nothing extra beyond the
      browser's own default — there is no tooltip), separated from the file
      name by a small centred dot: e.g. "Not saved yet · Untitled roster". The
      dot is decorative only — a screenreader hears "Not saved yet Untitled
      roster", not "dot". A first launch (or a
      brand-new document from **New**) reads "Not saved yet" and shows
      `file_save_off`, even though nothing has been edited — "Saved" is not
      true of a canvas nobody has written anywhere. One edit to that untitled document keeps reading "Not saved
      yet" — never-saved outranks dirty — and a **red bar appears above the
      canvas** naming "Save copy" as the way to keep the work. The first
      **Save copy** makes the bar disappear and the status read "Saved" with
      `file_save`. From then on, an edit reads "Unsaved changes" /
      `file_save_off` with no bar, and Save swaps straight back to "Saved".
      Never two icons and never none; hovering the strip brightens it and
      changes nothing else.
- [ ] **Never-saved warning bar** — open the app fresh (or **New**): the canvas
      shows no red bar. Type or edit anything: the bar appears above the chart,
      reading the exact phrase "Save copy" (the same words on the Start ribbon's
      Save button). Click **Save copy**, pick a name: the bar disappears and does
      not return on further edits. PNG and PDF export are unaffected by any of
      this — confirm both still export correctly.
- [ ] **Save As** — the dialog is pre-filled with the current name, Enter accepts
      it, and Escape cancels without writing a file.
- [ ] **Open** — `test/fixtures/current.json` loads with 9 grades and 26 people.
- [ ] **Open with unsaved changes** — warns first, and cancelling really cancels.
- [ ] **Open shows a status** — the status bar reads "Opening current.json …"
      while it works, and the message clears once the roster is on screen.
      Use a roster with many photos, or the pass is too quick to see.
- [ ] **Close the tab with unsaved changes** — the browser's leave-site prompt appears.
- [ ] **Sparse file** — `test/fixtures/legacy.json` opens with 4 grades, every
      setting it omits at its default and the photos framed as full circles.
      Nothing is reported as repaired — absent is not a repair.

there is time to act. In every case: nothing appears, the undo list gains no
entry, the title bar shows no unsaved-changes dot, and a message says why.
- [ ] Drop a batch, then press **New** before it finishes.
- [ ] Drop a batch, then **Open** another roster before it finishes.
- [ ] Drop a batch, then apply a **template** (Structure ▸ Templates), then
      **Undo**. The old grades are back with the same ids, and the batch still
      does not land.
- [ ] Repeat with **Clear grades**, then **Undo**; the batch still does not
      land in the restored grade.
- [ ] Drop a batch aimed at a grade, then delete that grade while it decodes.
- [ ] With two photoless people in the roster, drop photos for both, then delete
      one of them mid-decode: the other photo still attaches, the message names

- [ ] Replace a photo, then delete that person before it finishes.
- [ ] Replace a photo, then press **New** before it finishes.
- [ ] Replace a photo, then **Undo** an earlier edit before it finishes.
- [ ] Sanity check the other direction: drop a batch, make an ordinary edit

**Photos inside a roster file.** `test/import.js` §10 drives these against a
decoder written for the suite, which reads JPEG SOF and PNG IHDR out of the real
bytes. What it cannot answer is whether a browser agrees, and that is the only
question that matters at the point of use — so open `test/fixtures/photos.json`
in each browser and confirm:
- [ ] Both "Valid Jpeg" and "Valid Png" keep their pictures.
- [ ] "Corrupt Jpeg", "Corrupt Png" and "Svg Wearing Jpeg" appear as initials,
      are still in the roster, and are named in the toast.
- [ ] Nothing in the console reports a failed image load — the photos were
      dropped during the open, so nothing broken should reach a renderer.
- [ ] Export a PNG and an SVG afterwards: neither carries a broken image.
- [ ] Save the opened roster and reopen it — the corrected dimensions are what
      was written, so the second open reports no repairs at all.
- [ ] **Two Opens at once**: open a roster with many large photos, and before it
      lands open a small one. The small one stays. Then do it the other way
      round — small first, large second — and the large one wins. The rule is
      "the last file picked", never "the first to finish".
- [ ] With DevTools' network tab open and offline mode on, open a roster whose
      photos are remote URLs (`test/fixtures/injection.json`) — **zero
      requests**, and those people show initials.

**The image preflight, in a real browser.** `test/import.js` §11 builds the byte
structures and proves what is refused before `Image.src`. What no suite can see
is the browser's own decoder agreeing, so with DevTools open:
- [ ] Open a roster containing a hand-edited photo whose PNG IHDR declares
      60000×60000. That person shows initials, the toast names the pixel limit,
      and the **Memory** graph does not move — the decoder was never asked,
      so a maliciously large declared size cannot exhaust memory or crash
      the tab.
- [ ] Swap a roster's JPEG payload for PNG bytes, leaving the `image/jpeg`
      label. That photo is dropped as unreadable; nothing appears in the console
      about a failed image load, because nothing was loaded.
- [ ] A photo taken sideways on a phone (EXIF orientation 6 or 8) still opens and
      is framed the right way up — browsers apply the rotation, so the decoded
      dimensions are the frame header's transposed, and that is accepted.
- [ ] A roster of ordinary photos opens quickly: the preflight reads at most
      the first 512 KB of each one.

recording:

- [ ] Pick only the unreadable file: the error *does* appear, and the status
      clears.
